# 导入元素定价

> 文件放进数据包的 `data/<命名空间>/element_mappings/`，`/reload` 生效。**文件名在这里不起作用**，真正定价的是文件里的 `block`、`item` 与 `build_cost`。

元素映射是"这件东西值多少元素"的唯一账本。合成站做它要花多少元素、工作站分解它出多少、商店按什么价卖它、探索宝箱里翻出它算多少钱、乃至它算不算"要料的建材"——全都查这一张表。

## 字段

| 键 | 说明 |
|---|---|
| block | 定价一个方块，写方块注册 id |
| item | 定价一个物品，写物品注册 id |
| build_cost | 元素到整数的映射，键取七元素之一 |
| disabled | 布尔值，把它排除出元素经济 |

## block 与 item

`block` 与 `item` 写一个就够，两个都不写等于这份文件没有意义。写成方块时，它的物品形态跟着一起有价；反过来只写 `item`，方块形态查不到它。

## 值被谁用

`build_cost` 是这个物品的**标准价值**，不是"放它要花多少材料"。向它要价的地方有好几处：工作站的合成任务按它扣元素；分解一件物品的产出是价值除以分解除数（除数可在设置中心调）；商店在它的基础上加利润卖出；探索宝箱按它给整张战利品表估价；扫描器按它估一块地值多少元素。

## 没有映射就是免费

建筑和道路只向仓库申请**有映射**的方块投料。一个方块没有映射，它永远不会被申请——所以把物品 id 打错一个字母，不会有任何报错，只会让那个方块变成白拿的料，建筑照样盖起来。这是这张表最容易吃亏的地方。

## disabled 有牙齿

`disabled` 不只是"不参与经济"：任何含有这个方块的建筑或道路会被**直接拒绝放置**——一条"禁用不能变成免费"的硬规矩。目录里那个 `disabled/` 子文件夹没有任何特殊含义，扫描是递归的，里面的文件照常加载；真正的开关只有这个字段。

## 覆盖模组自带的映射

要改掉模组已经写好的某个价格，你的文件必须放在 **`wandscape` 命名空间、用同一个文件名**，靠数据包优先级盖过去。另起一个文件名不管用：注册的主键是剥掉命名空间后的文件名，撞车时模组自己那份优先，你的文件会被整个丢掉；即便绕过撞车同时留下两份，查表取的是哈希顺序里的第一条，谁生效不确定。

## 写错一个键的代价

写错一个元素键（比如把 `metal` 写成 `matel`），整份文件会解析失败并被丢弃，日志里留一条警告——只有这一种错会出声。

## 元素种子

模组里另有一份 `element_seeds.json`，是一张约四百条的手写基准价目表。它**只**是一条开发命令的输入，游戏里不参与定价，也没法被数据包覆盖。

## 生成命令

`/wandscape test generate_element_mappings` 会拿种子作基准、按原版配方反推出一整批映射文件，可以用 `--dry-run` 先看、`--force` 强制覆盖已经存在的手写文件。

注意它写的是**开发者的源码树**，只有在自己电脑上改模组数据时才用得上，别在服务器上跑。
