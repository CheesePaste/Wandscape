# 导入自定义建筑

> 建议先看[建筑扫描器](building_scanner_guide.md)：扫描器导出的那份文件，就是本篇要讲的东西。手写只在要批量生成、或者要精修扫描结果时更划算。

建筑文件放进数据包，`/reload` 之后它就会出现在建造面板和建造法杖的列表里。**文件名只决定它归哪个包，文件里的 `id` 才是建筑的权威标识。**

## 文件放哪里

路径是 `data/<命名空间>/buildings/<id>.json`，命名空间随便取，不必叫 `wandscape`。要覆盖模组自带的建筑，才必须放进 `wandscape` 命名空间、用同一个文件名。

`buildings/` 下的**第一层子目录名就是建筑包**：`data/xxx/buildings/medieval/inn.json` 属于 `medieval` 包。放在 `buildings/` 根下的归 `default` 包。详见[导入建筑包](custom_packs_guide.md)。

## 最小可用的一份

| 键 | 说明 |
|---|---|
| id | 建筑标识，写文件里的这个，不是文件名 |
| category | 分类，面板里归哪一栏 |
| pattern | 方块坐标，每项三个整数 |
| palette | 方块状态列表 |
| block_indices | 与 pattern 等长，指向 palette |
| blueprint | 施工蓝图，漏了它就不进面板 |

## 蓝图这一项

`blueprint` 是最容易漏的一项，漏了的表现是：加载日志一切正常，建造面板里却怎么都找不到这个建筑。它的内容从扫描器的导出里原样抄下来就行，两个字段分别是 `id`（用哪套施工逻辑）与 `bind`（哪些蓝图参数取建筑的哪个字段）。

`bind` 的取值要写成带前缀标记的字段名，形如脚本里的变量引用。自己编排这套绑定没有意义，直接把扫描器那份抄过来。

## 几何三个字段

`pattern`、`palette`、`block_indices` 搭起来才是建筑：pattern 是坐标，palette 是方块状态表，block_indices 把每个坐标指到表里的一项。三者的长度与取值范围会在加载时校验，对不上就整份文件被丢弃并留一条警告。

## 包围盒与方块数据

`boundary` 是包围盒（`min` 与 `max` 两个坐标），缺一个都会让文件解析失败。它和 pattern **不做一致性检查**：pattern 可以落在盒外，盒内的非 pattern 空间则是建造时"清盒"要清理的范围。

`block_nbt` 存方块实体数据，生存扫描器导出时会整段剔除。旧格式里的 `block_mapping` 字段现在写了就直接报错，换成 palette 加 block_indices。

## 门

`door_offsets` 是游客进门的候选格（数组，可写多扇）。不写的时候，游客会沿包围盒边缘往里钻——房子悬空或者埋在地下，他们就找不到入口。旧键名是单数的 `door_offset`，还能读，但别再用。

## 交互位

`interact_spots` 是游客站的位置，每项三个键：`pos` 是相对锚点的坐标、`action` 是做什么、`facing` 是面朝哪边。`action` 取 `browse`、`eat`、`bathe`、`view`、`pay`、`read`、`take`、`rest`、`withdraw` 之一；`facing` 取 `north`、`east`、`south`、`west` 之一。写错这两个**不会报错**，会被静默改成 `browse` 与 `south`。

## 交互位的数量

一个建筑可以有多个交互位，同时能接待的游客数就等于交互位数量，所以**一个交互位都没有的建筑对游客完全无效**——它会照常建起来、照常被算进小镇，游客就是不来。

## 分类

`category` 是一个自由字符串，不校验，但它决定建筑落在建造面板的哪一栏。市政厅、仓库、工作站、合成站、魔法工坊、酒馆、祭坛这几类在代码里另有地位，写错分类会让建筑失去那份身份。

## 参数段

游客相关的参数段有四组：`shop`、`service`、`relax`、`atm`，采集节点则用 `node_config`。**参数段和 `category` 并不联动**：决定一个建筑算不算游客目标的是它有没有写上那四组之一，`category` 只影响归类与排序。写了 `shop` 段却把 `category` 填成别的，游客照样来买东西。

## 三值与门槛

`comfort`、`magic`、`wonder` 是三值，决定它能满足游客哪方面的需求。`unlock_requirement` 是小镇等级门槛，**整个省略时不设门槛（等级 1）**，写成空对象 `{}` 则等于门槛 0——两者语义不同，别随手写成空对象。

## 写错了会怎样

- 缺 `id`：跳过这一条，日志里一行警告。
- 语法或几何校验不过：整条丢弃，日志里一行警告，其余建筑照常加载。
- 方块 id 打错：加载期不报错，建造到那一格时直接跳过，盖出来的房子会缺一块。
- `blueprint` 漏了或者 id 写错：前者是面板里找不到它，后者是建造任务展开时抛异常。这两种都不在加载期出声。

## 改完怎么生效

`/reload` 一次就够：服务端重读、客户端重新同步都包含在里面，不用重启也不用重进。唯一不会自动刷新的是**已经开着的建造面板**，退出再进一次建造页才会看到新建筑。

`/wandscape building list` 可以列出当前认识的建筑，`/wandscape fill <建筑 id> <间距> <数量>` 能直接把它摆一片出来做验证——id 打错时这条命令会把所有已知 id 回显给你。
