# 指南书文体规范

本文件是 `src/main/resources/assets/wandscape/guide/{zh_cn,en}/*.md`（游戏内指南书）的写作标尺。约定指南书该怎么说、避免怎么说，防止文体走偏成「陪聊调侃 + 废话文学」。读者：所有撰写或改写指南书的人（含 AI）。

## 目标文风：平实中性教程

指南书是教程，不是陪聊。每篇开门见山讲「这个东西做什么、怎么操作、有什么代价」，让玩家用最快速度查到机制与数值。

- **保留**：第二人称（「你」）、游戏设定词（法师、元素、魔法、奇观、殖民地等级）。
- **清除**：见下方「清零清单」。

## 三原则

1. **开门见山**——第一句讲功能，避免先抛比喻。游戏概念（元素、建筑功能）本身清晰，现实映射（钱庄、大脑、双手、铸币厂）既不精确又增加阅读负担。
2. **信息密度优先**——数值、配方、解锁条件、概率用表格或列表承载，避免散文化包裹、埋在句中段。
3. **语气中性**——平实陈述，零调侃、零教训、零俏皮。可以解释「为什么」，但避免当读者的保姆（「别慌」「别怕」「别急」）。

## 结构模板

各篇按需取用，不强求全部具备：

```
# <emoji> <名称>
<一句话功能定义，无比喻>

## <核心机制 / 页签 / 分类>
<表格承载数值与解锁条件>

## 操作
<箭头串接步骤：A → B → C → Submit>

## 注意 / 代价
<引用块或列表承载副作用与警告>

---
<文末导航：上一篇 / 下一篇 / 返回首页>
```

## 清零清单（改写时逐条排查）

| 毛病 | 避免这样 | 改成这样 |
|---|---|---|
| 牵强比喻 | 工作站是元素的钱庄；市政厅是大脑；节点是铸币厂；仓库是命脉 | 工作站分解建材、合成物品（直说功能） |
| 调侃 / 教训腔 | 靠它发财没门；别慌；别怕；别急；别乱花；看脸；放心穿；等等就好 | 删掉，直接陈述机制 |
| 同义反复废话 | 拆是应急，合是消费，两头都能用；各有妙用；A→B→A 正循环 | 删掉整句（零信息） |
| AI 味补充括号 | （顺带一提：…）；（那个小人真的会…）；（看脸） | 写成正文一句，或删 |
| 元注释（讨论文章本身） | 所以它值得单独占一章；这步最不能省；这句不是比喻 | 删掉，不和读者讨论文档结构 |
| 陈词套话收尾 | 救命稻草；金贵；一眼扫完；家底 | 写出具体区别或作用 |
| 拟人调侃机制 | 别指望法师自觉；表格里写「谁出事了」 | 用机制语言描述 |

## 正面基准（向这些段落看齐）

当前指南里最像正经教程的段落，是改写的目标参照：

- `crafting_guide.md` **法杖表**——纯数值表（法杖 / 殖民地等级 / 成本 / 加成），一眼查到所有门槛，无比喻无废话。
- `npc_guide.md` **属性表**——生命 / 魔力 / 速度 等，逐条一行。
- `road_spline_guide.md` **画曲线步骤 + 常见问题**——编号步骤 + 现象→原因→对策。
- `overview_guide.md` **快捷键表**——按键与作用两列对应。

共同特征：**表格 / 编号列表承载机制与数值，正文不堆比喻、不夹调侃括号、不做元注释。**

## 格式约束（自研 Markdown 引擎）

引擎见 `MarkdownParser.java` / `MarkdownRenderWidget.java`，决定可用语法：

- **可用**：H1–H3、行内格式（`**bold**` `*italic*` `` `code` `` `~~strike~~`）、`[text](doc_id.md)` 链接、`>` 引用块、无序 / 有序列表、GFM 表格、独立行图片 `![alt](wandscape:textures/gui/guide/xxx.png =WxH)`。
- **不可用**：H4+、嵌套结构（列表内表格等）、frontmatter、HTML、脚注、任务列表。

**链接与导航约定**：正文统一 `[文本](doc_id.md)`（GitHub / IDE 可点击跳转）；每篇正文末尾 `---` 分隔后给「上一篇 / 下一篇 / [📖 返回指南首页](index_guide.md)」，每条两空格结尾换行。

## 事实纪律

- 改文体**不改事实**：所有数值（折价率、成本、概率、门槛）严格保留原值。
- 已知事实错误记录在 [gaps.md](gaps.md) 第六节（如「声望机制虚构」）。文体重写时**保持原意、只删修辞**，事实修正另开任务，不在文体任务里顺手改。
