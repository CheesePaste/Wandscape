## 二、游客线元素产出

### 2.1 解析口径（A5，按档）

口径来自 `calc_balance.py` 的 A5 段（解析上限口径：商店补满不计成本、游客全住得下、停留消费按 2× 钱包估、**不含服务建筑的 elementOutput**）。所以这是**上限**，真实值更低。

> 2026-09-26：商店的 `profit_rate` 全表减半（1.0→0.5、0.8→0.4、0.7→0.35、0.6→0.3、0.5→0.25），下表已按新值重跑。
> A5 只把**毛利**算作产出（`利润 = profit_rate × 单价 × 数量`），所以利润率的这一刀就是产出的精确一半；
> 而实际入账是 `cost × (1 + profit_rate)`（成本那半不动），真金白银只降 17%–25%。两个口径别混。

两个形状特征：

- **wood 一直是最大项**（占 32%–43%），metal 次之。每一档的**瓶颈元素**分别是 wood（1→5、5→10）、earth（10→15）、dark（15→20）——瓶颈不在产出最多的那一项，而在产出最少的项。
- 游客线随殖民地等级增长 **11.7 倍**（13,501 → 158,130），因为游客数量、钱包、商品档位都跟着等级涨。

攒钱天数（A5 口径，目标 = 下一档新增建筑造价 ÷ 日利润）：前三档 **5–6 天**，15→20 档要 **40 天**（瓶颈 dark）。所以**造价不是瓶颈**，三值推进才是。

## 三、探索线元素产出

口径：每个结构「一张战利品表 = 一箱」的算术平均；exp 与元素同源（`exp = 元素总值 ÷ exp_ratio`，`exp_ratio = 5.0`，无危险乘数）。模组**不自带声明区域**，原版结构与其他模组一样落在生成档（`mode: fixed`，值 = 估价器算出的期望），数字由 `balance/explore_reward.py` 复算，已对 22/22 张原版格式表与游戏落盘值逐字节对齐。本次删声明区域**不改任何数字**：生成档写下的值就是 `derived` 会现算的那个期望，`exp_ratio` / `variance` / `loot_share` 三项也都仍是 `DEFAULT`。

> 2026-09-27 重跑确认：**下表逐表数值与本版一致**（漂移 ≤2，纯取整），本节无需改动。
> 本机存档已装入第三方模组，重跑后的 `out/explore_reward.txt` 多出 goety / irons_spellbooks / touhou_little_maid / artifacts / cataclysm 以及试炼密室、堡垒各表（实测区域 173 个、战利品表 2534 张）；
> 本文 §3 仍**只覆盖原版地貌**那 10 组，第三方与新增原版结构不进本表。

**元素一律按「玩家实际到手」算，不是估算向量。** 两者差别很大，别混：估价器产出的价值向量是**战利品形状**的（极度偏 metal），而 `ExplorationRewardRange.rollElements` 发放时会按 `loot_share`（默认 0.5）保留一半形状、把另一半总额平摊给七元素。于是到手金额近似 `value[e]/2 + 总额/14`——末地城的估算向量是 100% metal，到手只有 57%。`out/explore_reward.txt` 的 B/C 段列的是**估算向量**，F 段才是到手口径。

表里的元素数字**已乘 `Config.exploration.elementMultiplier`（当前 1.0，即估价原值）**，经验数字已乘 `expMultiplier`（当前 1.0）。2026-09-26 把 elementMultiplier 从 2.0 调回 1.0，下表已是调回后的数（上一版表里的元素数字除以 2 即可对上）。表里「一箱 = 天游客线」两列不变：游客线同期也减半（§二），分子分母同除 2。

### 3.2 结论：头部三个结构够用，腰部以下偏紧，且随等级迅速贬值

1. **头部结构很慷慨。** 下界遗迹平均一箱 ≈ 3.43 天整个殖民地前期的游客产出（其中两张宝库表各 ≈ 7.4 天），末地城 1.04 天、远古之城 0.88 天。**但这是前 3 名**——第 4 名起掉到 0.68 天以下，村庄/要塞只有 0.05–0.06 天。
2. **形状没有看上去那么歪。** 到手后 metal 占 25%–57%，其余六元素各分到约 7%。瓶颈元素（wood / earth / dark）每箱能拿 **50–3,350**，不是估算向量显示的 0。按瓶颈元素折算：头部结构 0.17–0.85 天，中段 0.04–0.14 天，村庄/要塞 0.01–0.02 天。
3. **越到后期越不值钱。** 游客线随等级涨 11.7 倍，箱子价值固定，所以同一箱从「3.43 天」缩到「0.29 天」。探索是**前期加速器**，不是中后期补给线——15 级之后最强的箱子也只值 0.29 天的产出。

一句话：**「元素产量低」的直觉在结构分布上成立**——十个结构里只有头部三个是真补给，腰部以下给的不到一天的零头；而在元素形状上，`loot_share` 的平摊已经把 metal 偏斜稀释掉一大半，瓶颈元素并不像估算向量看起来那么惨。2026-09-26 已把 `elementMultiplier` 从 2.0 调回 1.0（经验不动），上表是调回之后的数。

次要原因（占比小，别当主因）：原版战利品表里最常出现却**没有 `element_mappings`** 的物品是 `minecraft:enchanted_book`（约 4.6 次/箱，因为附魔类函数会把书换成附魔书，而映射表里没有附魔书），其次是 `suspicious_stew`、各种 `*_armor_trim_smithing_template`、`filled_map`。把它们按同类补上价，箱子价值只涨 **0.3%–4%**。

### 3.3 结构间的价差来自 metal 映射

`minecraft:netherite_ingot` 一锭 = **fire 16,384 + metal 33,792 = 50,176** 元素值（对照：`diamond` 1,024、`iron_ingot` 64、`emerald` 256）。堡垒宝藏表的**估算向量**（未过 loot_share、未乘倍率，即 B/C 段那个数）因此被顶到 10 万级，与村庄的 666 拉开 **150 倍**。要压探索的价差，动这里比动任何区域参数都直接——但它是全局建造经济的共用映射，改前先看 `calc_balance.py` 的 A1 造价表。

## 五、怎么刷新这张表

`balance/` 不入库，工具都在那里。改完建筑 JSON 或数值后：

```bash
cd balance
python extract_buildings.py                 # 刷新建筑造价/三值
python _tier_analysis.py                    # 刷新各档造价/三值/元素占比聚合
python calc_balance.py                      # 刷新 §2.1 游客线（A5 段）
python sim_spatial.py --scenario prog --days 500   # 刷新 §1.3 prog 曲线 + §2.2 数据源
python sim_spatial.py --scenario idle --days 200   # 刷新 §1.3 挂机线
python _level_income.py out/sim_prog.json out/sim_idle.json   # 刷新 §2.2 按等级元素收入 → out/level_income.txt
python explore_reward.py                    # 刷新 §3 探索线 → out/explore_reward.txt
```

`_level_income.py` 必须在两个 sim **之后**跑：它读的是 `out/sim_*.json` 里落盘的逐日 `history`，不是重新模拟。

然后把上面对应的表**手工搬到本文**——这一步没有脚本，靠人。所以：

- 只改了「快照数字」相关的数值却没回来更新本文，本文就是错的，比没有更糟。
- §1.1、§4 是代码常量，改代码时顺手改，不依赖跑工具。

### 快照本身的已知偏差

- **生成档会与默认值静默分叉**：`<world>/wandscape/generated_regions/` 是「某次运行时」的快照，启动时只要匹配到就跳过重算。改过默认值（如 `exp_ratio`）后，老世界的生成文件仍按旧值结算；本文 §3 引用的是**当前代码默认值**，不是某个存档里的旧值。清掉该目录、下次开服即重写。
  原版结构现在也在这一档（模组不再自带声明区域），所以这条对 §3 的全部数字成立，不再只是「其他模组的表」的问题。
- **`irons_spellbooks` 的战利品表复算不准**（4/44）：它用了自家 entry/function 类型，`balance/explore_reward.py` 没复刻。本文 §3 只覆盖原版结构，不受影响。
- **`*/inject/chests/*` 载荷表不折 exp**：那是全局战利品改装的注入目标，估价器只读宿主表的 pools、不跑 loot modifier。共 50 张，已从统计中排除。
- **A5 不是 sim**：§2 是解析上限口径，真实体验以 `sim_spatial` 为准（后者含视野/移动/排队/精力/visited 约束）。两者对不上时按 sim 保守调整、用 A5 验证方向。
