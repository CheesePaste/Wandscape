## 一、模块拆解原则

1. **两层依赖**：每个模块可依赖 `01-shared-api`（接口层）和/或 `08-building-core`（建筑基类层）。禁止依赖 02-07 和 09-16 中的任何其他模块。
2. **独立测试**：每个模块可在无其他模块的情况下单独编译和单元测试。
3. **数据驱动**：建筑、法杖、配方、元素等可扩展内容全部 JSON 定义，不硬编码。
4. **接口先行**：模块间通过 `01-shared-api` 中定义的接口通信，不直接引用对方类。

## 四、开发约定

### 4.1 API 设计

- 每个模块对外暴露一个或多个接口，全部在 `01-shared-api` 中定义。
- 模块实现类为 internal，不对外暴露。
- 通过注册表（Registry）查询实现，而非直接 new。

### 4.2 数据驱动

以下内容必须 JSON 定义：
- 建筑类型（名称、三数值、维护成本、队列容量、可发布的任务类型）
- 法杖配方（需要的元素、NBT 预设）
- 元素定义（ID、显示名、所属层级）
- 方块→元素映射（#wandscape:decomposable 标签的方块及其分解产物）
- 节点建筑产出（元素类型、每次产出量、引导时间）
- 仪式定义（引导时长、需求法杖等级、消耗、效果）

### 4.3 注册表约定

Wandscape 使用 NeoForge 的 `DeferredRegister` 注册以下内容：
- 物品（法杖等）
- 方块（建筑方块）
- 方块实体（建筑用 BE）
- 实体（NPC）
- 菜单类型（GUI Screen）
- 创造模式物品栏

### 4.4 事件通信

模块间通信使用 NeoForge EventBus。`01-shared-api` 中定义所有事件类。模块 A 触发事件，模块 B 监听事件，两者不互相引用。

**优先级约定**：所有监听器使用默认优先级（`EventPriority.NORMAL`）。若某模块需在其他模块之后处理（如建筑核心需在任务系统之后更新状态），改用 API 直接调用而非依赖事件顺序——事件仅用于解耦通知，不用于编排处理顺序。

示例：
```java
// 01-shared-api 中定义
public class TaskCompletedEvent extends Event {
    private final Task task;
    // ...
}

// 06-task-system 中触发
NeoForge.EVENT_BUS.post(new TaskCompletedEvent(task));

// 08-building-core 中监听
@SubscribeEvent
public void onTaskCompleted(TaskCompletedEvent event) { ... }
```

### 4.5 测试约定

**测试分层**：

| 层级 | 范围 | 技术 | 示例 |
|------|------|------|------|
| 单元测试 | 纯逻辑：枚举、校验、JSON 解析、数据并集、类型映射 | JUnit 5, 零 MC 依赖 | `AbilitySetTest`, `WandDataValidatorTest` |
| 集成测试 | MC 运行时：方块交互、物品 NBT、实体行为 | `@GameTest` (未来) | `WandApiImpl` 集成测试 |
| 手动测试 | UI/渲染/GUI | 手动清单 | 法杖物品模型颜色渲染 |

**单元测试强制要求**：

1. **所有不依赖 Minecraft 运行时的纯逻辑代码必须有单元测试。**
   纯逻辑定义：不通过任何路径依赖 `Minecraft.getInstance()`、`ItemStack`、`BlockState`、`Level`、`ServerPlayer` 或任何需要 MC 初始化才能工作的类。
2. 测试类放在 `src/test/java/` 下，包路径与被测类镜像。
3. 每个测试方法命名使用 `lowerCamelCase`，清晰描述场景和预期结果。
4. 每个方法至少覆盖：正常路径 + 边界条件（null/空/负数/最大值）+ 错误路径。
5. `./gradlew test` 必须全绿才允许提交。

**测试工具栈**：

- JUnit 5.10（platform BOM + Jupiter engine）
- 不使用 Mockito、AssertJ 或其他第三方测试库（遵循最小依赖原则）
- `CompoundTag` 可独立构造（`new CompoundTag()`），无需 MC 实例
- `com.google.gson.JsonParser` 用于构造测试 JSON 输入

**不可单元测试的情况**：

- 构造器继承 MC 类（如 `SimpleJsonResourceReloadListener`）
- 方法参数包含 `ItemStack`（需要 `DataComponents.CUSTOM_DATA`）
- 方法参数包含 `BlockState`（需要 `BuiltInRegistries.BLOCK`）
- 任何调用 `Minecraft.getInstance()` 或 `net.minecraft.server.MinecraftServer` 的代码

这些情况应在文档中明确标注，等待集成测试阶段覆盖。

## 五、关键术语速查

| 术语 | 含义 |
|------|------|
| 法杖 | NPC/玩家携带的物品，NBT 定义行为标签和等级。永不损坏 |
| 行为标签 | 法杖 NBT 中的键值对（如 `building:3`），声明能力领域和等级 |
| 元素 | 抽象资源，分三层共 9 种，替代实体建材。存储于殖民地仓库 |
| 原子操作 | NPC 工作的最小单元：A 方块转化、B 建筑交互、C 实体交互、D 仪式 |
| 任务池 | 殖民地全局任务队列，调度器每 2 秒分配一轮 |
| 私有池 | 每个 NPC 自己的任务队列，优先级高于全局任务 |
| 建筑队列 | 每个建筑内部的任务队列，逐个发布到全局池，容量因建筑类型而异 |
| 三数值 | 舒适值、魔法值、奇观值，由建筑首次建造提供，驱动殖民地发展 |
| 维护成本 | 建筑定期消耗木元素，不足不损坏只降效率 |

| 阶段 | 名称 | 模块 | 累计成果 |

| 原计划 | 新路线 | 理由 |

| P0: 05 原子操作先于 08 建筑 | 08 建筑先于 05 原子操作 | OperationB 需要建筑 BE 存在才能测试 |
