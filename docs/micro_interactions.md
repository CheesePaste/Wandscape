# 装饰建筑微交互系统（Micro Interactions）

文档编号：11
版本：0.1
状态：概念设计

## 一、设计目标

1. **让"纯装饰"不再仅仅是摆设**：部分高级装饰建筑获得与游客的轻度交互能力，玩家看到游客在使用装饰物时获得成就感。
2. **低成本高存在感**：都是简单的被动效果或单次触发，不需要复杂的状态机或寻路导航。
3. **世界观填充**：长椅、喷泉、花圃等细节让殖民地更像一个真实的小镇，而非纯功能建筑集合。
4. **定位**：不是经济系统的核心环节，不具备平衡性压力。效果可有可无，但存在就能增加世界感。

## 二、设计原则

1. **游客不需要特意前往**：微交互都是路过触发或近距离被动生效，不需要游客特意寻路到该位置。游客按原有 AI 路径行走，在路过时自动触发。
2. **数值微小**：每次效果 1-5 点精力值或满意度。累积效果显著但单次几乎不可感知。
3. **不重复触发**：同个游客在短时间内（建议 5-10 分钟游戏内）不会从同个交互物反复获得收益。
4. **不影响现有核心循环**：Shop/Service 经济闭环仍然是玩家收入的主要来源。微交互是添头，不是替代。

## 三、交互类型

### 3.1 恢复类

游客在路过或靠近时被动获得少量恢复：

| 交互物 | 适用建筑 | 效果 | 触发方式 |
|-------|---------|------|---------|
| 长椅 | 公园/广场类装饰 | +2 精力值 | 路过时（半径 2 格内） |
| 喷泉 | 水主题装饰 | +1 满意度 | 路过时（半径 3 格内） |
| 篝火 | 火主题装饰 | +1 精力值 +1 满意度 | 路过时（半径 3 格内） |
| 香炉/熏香台 | 风主题装饰 | +1 满意度 | 路过时（半径 3 格内） |
| 花圃 | 土主题装饰 | +1 满意度 | 路过时（半径 2 格内） |

### 3.2 观赏类

游客短暂停留，获得一次性效果：

| 交互物 | 适用建筑 | 效果 | 触发方式 |
|-------|---------|------|---------|
| 雕塑/雕像 | 奇观/高级装饰 | +3 满意度 | 游客在建筑附近逗留时触发（概率 30% 每次路过） |
| 观景台 | 风主题高级装饰 | 精力值 +2, 满意度 +1 | 游客走到附近时触发 |
| 钟楼 | 金属主题装饰 | 满意度 +2 | 整点附近触发（30 格内自动获得） |

### 3.3 庇护类

提供轻度舒适感：

| 交互物 | 适用建筑 | 效果 | 触发方式 |
|-------|---------|------|---------|
| 凉亭/遮阳篷 | 木主题装饰 | +1 精力 | 游客在下方停留时 |
| 路灯 | 沿路装饰 | 夜间满意度不因黑暗衰减 | 路过时持续生效 |

## 四、JSON 配置

微交互通过装饰建筑 JSON 新增字段配置：

```json
{
  "id": "garden_bench",
  "display_name": "花园长椅",
  "category": "decoration",
  "elements": ["earth"],
  "comfort": 2,
  "magic": 0,
  "wonder": 0,
  "maintenance_cost": {
    "interval_ticks": 12000,
    "costs": { "earth": 1 }
  },
  "decoration": {
    "radius": 8
  },
  "micro_interactions": [
    {
      "type": "restore_energy",
      "amount": 2,
      "range": 2,
      "cooldown_ticks": 6000
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| type | string | 交互类型：restore_energy / restore_satisfaction / restore_both / admire |
| amount | int | 恢复数值 |
| range | int | 触发半径（曼哈顿距离） |
| cooldown_ticks | int | 游客单次触发后的冷却时间（默认 6000 = 半天游戏内） |

每种 buildingId 只允许一个微交互条目（避免配置膨胀）。

## 五、游客侧行为

- **游客不需要导航到微交互建筑**：微交互直接在 TouristMoveGoal 的移动路径中检查。
- 每 tick 检查当前游客所在位置附近（range 内）是否有带 `micro_interactions` 的建筑。
- 检查该游客是否在冷却中 → 不在冷却中则触发 → 进入冷却。
- 触发时仅数值变化，无交互动画（当前阶段）。
- 触发不影响游客的当前 MoveMode（WANDERING/EXPLORING 期间都可以触发）。

## 六、与元素系统的关系

微交互与元素系统**弱关联**：微交互不依赖元素系统运行，但设计上可以体现建筑的元素主题：

- 火主题装饰 → 篝火类交互（恢复精力/满意度）
- 水主题装饰 → 喷泉类交互（恢复满意度）
- 风主题装饰 → 观景/香薰类交互（恢复满意度）
- 木主题装饰 → 凉亭/花圃类交互（恢复精力）
- 土主题装饰 → 园艺类交互（恢复满意度）
- 金主题装饰 → 钟楼/雕塑类交互（一次性加较多满意度）
- 暗主题装饰 → 不提供微交互（暗元素本身就是负面光环，不额外提供正面效果给游客）

这是设计建议，非代码强制。
