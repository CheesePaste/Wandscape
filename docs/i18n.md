# 多语言适配计划 (i18n)

> 目标：所有玩家可见文本支持按客户端 locale 切换（en_us / zh_cn），消灭数据 JSON 与代码里的硬编码显示文本。
> 本文档是实施蓝图。完成度随 P0–P5 推进更新，每个阶段独立 commit。

---

## 现状（2026-08-03 调查）

- 全项目仅 1 处 `Component.translatable`（`Wandscape.java:280`），其余玩家可见文本均为 `Component.literal` 直出。
- 玩家可见硬编码分两类：
  1. **数据 JSON 内嵌文本**：`buildings/*.json` 的 `display_name`（20 文件，英文 ID 与中文混杂：`"inn1"` / `"图书馆"`）、`craft_recipes/*.json`、`blueprints/*.json`、`narratives/`（仅 zh_cn）、`assets/wandscape/guide/*.md`（20 文件纯中文）。
  2. **Java 代码硬编码**：聊天消息（`Component.literal("[Tourist] ...")` 等 160+ 处）、GUI 标题/label、NPC/游客状态名、头顶气泡（115 处）、新手引导（99 处）、元素名。
- **已有正确示范**：`lang/en_us.json` + `zh_cn.json`（物品/实体/按键/进度/音效）、`advancement/*.json` 全部走 `"translate"` key。
- 不需要本地化的噪声：日志（`Log.*`）、注释、JSON 的 key/id 字段。

## 术语规范（强制，所有新增/改动遵守）

- 中文显示名统一用 **魔法小镇**，英文统一用 **Wandscape**。
- 玩家可见文本与 lang key **禁止** "殖民地" / "colony"——该词不能传达"玩家经营的小镇"语境，属不恰当翻译。
- 代码内部类名（`ColonyCommand` / `ColonyItemBank` / `ColonyMetricsApi` 等）是历史遗留的**代码标识符**，非玩家可见文本，本期**不重命名**（重命名超出 i18n 范围）；但**新建的 lang key 一律用 `town` 而非 `colony`**（如 `message.wandscape.town.*`）。
- 验收校验：P5 的 key 扫描断言 `en_us.json` + `zh_cn.json` 无任何 `colony` 前缀 key、无 `殖民地` 字符串。

## 核心设计决策

### D1 — 数据层存 key，不存文本

`display_name` 字段**语义不变**（仍是可读的默认文本，作 fallback），**新增由 `id` 派生的 lang key**：

| 数据 | key 约定 | fallback |
|------|----------|----------|
| 建筑 | `building.wandscape.<id>` | `display_name` |
| 配方 | `craft_recipe.wandscape.<id>` | `display_name` |
| 蓝图 | `blueprint.wandscape.<id>`（描述 `….<id>.desc`） | `display_name` |

- key 由 `id` 派生，**不需要改 JSON schema、不需要改网络包**（包已传 `id` + `displayName`）。
- 少数需要 key ≠ id 派生的场景，预留可选覆盖字段 `name_key`（本期不做，仅预留约定）。

### D2 — 命名空间约定（Java 代码字符串）

| 类别 | key 前缀 |
|------|----------|
| 聊天/系统消息 | `message.wandscape.<模块>.<动作>` |
| GUI 标题 | `gui.wandscape.<screen>.title` |
| GUI 内部 label | `gui.wandscape.<screen>.<label>` |
| 建筑分类名 | `category.wandscape.<category_id>` |
| 徽章 | `gui.wandscape.badge.<name>` |
| NPC 状态 | `npc.wandscape.state.<key>` |
| 游客状态 | `tourist.wandscape.state.<key>` |
| 元素名 | `element.wandscape.<id>` |
| 气泡 | `bubble.wandscape.<类别>.<序号>` |

### D3 — fallback 机制

客户端统一工具类 `shared/ui/I18n.java`（或 `shared/client/I18n.java`）：

```java
public static Component name(String key, String fallback) {
    return Component.translatableWithFallback(key, fallback); // lang 缺失时显示 fallback
}
```

> ⚠️ 实现前用 `minecraft-source` skill 确认 1.21.1 的 `Component.translatableWithFallback(String, String)` 签名。

### D4 — 服务端聊天消息发 translatable 组件

服务端不需要解析客户端语言。`Component.translatable("building.wandscape." + id)` 可在服务端创建，客户端按自身 locale 渲染。**禁止服务端 `Component.literal(displayName)` 拼消息**。

### D5 — 内容型文本走 per-locale 文件

narratives（已有 `LOCALE` 常量机制，见 P4）与 guide md 属于"大段内容"，不逐条 key 化，用按语言分文件/分目录。`NarrativeTemplates.LOCALE` 当前硬编码 `"zh_cn"`（`NarrativeTemplates.java:41`），需改为从客户端 locale 或资源探测。

3. **新建 `I18n.name(key, fallback)`** 工具（D3）。
4. **客户端渲染点改 key**（核心）：
   - `BuildingSelectionOverlay.java:399` 卡片名 → `I18n.name("building.wandscape."+slot.id(), slot.displayName())`。注意 398–407 行的**截断逻辑**改用 `Component` 宽度。
   - `WandscapePanelController.java:329` 选中提示 `"???"` → `Component.translatable("building.wandscape."+slot.id())`（带 fallback）。
   - `TouristDataPacket.java:136`、`TouristMoveGoal.java:1586`、`HotelStayHandler.java:261`（气泡目标建筑名）→ 客户端渲染处改 key。

   - `ProjectionPlacePacket.java:91,97` `[Projection] Placed '<name>'` → 嵌入 `Component.translatable("building.wandscape."+config.id())`。

8. **commit**：lang 补齐 → commit；渲染点改造 → commit；服务端消息 → commit。

## 风险与注意事项

1. **`Component.translatableWithFallback`**：1.21.1 签名需 `minecraft-source` skill 核实；若不存在则自定义 key 缺失探测。
