# 目标效果说明书（Goal / Design Intent）

> **这是整套改造的「北极星」**。所有 block 的 AI 开工前先读本文件，理解「要做出什么样的体验、为什么」。当某 block 文档没写清楚细节时，以本文件的意图为准去推断，**不要自己发挥偏离目标**。

## 一句话定位

把游客从「碰一下建筑就进 CD、然后干晃悠的贴图」变成「**真的在城镇里生活的访客**」：他们在面包店排队、在澡堂泡澡回精力、在 ATM 取钱接着逛、在旅店睡觉、满意了就开心回家；同时让**休闲建城玩家不被数值最优解绑架**——普通建筑不会被嫌弃，多样化的城镇自然能带来满意的游客。

## 玩家体验目标（要做到的感觉）

1. **休闲友好**：没有任何「建筑数值不够就扣游客好感」的惩罚。玩家随手建的普通建筑，游客逛了也涨（哪怕涨得少）。几条高级建筑 + 游客待 2-4 天，就能让游客满意、殖民地拿经验。
2. **多样城镇，而不是堆最强**：游客每人有自己的「画像」（更看重舒适/魔法/奇观之一）。要喂饱不同画像的游客，城镇自然需要三类建筑都有覆盖。玩家会**自己**觉得「哦，得补点魔法建筑」——不是被惩罚逼的，是游客行为引导的。
3. **城镇是活的**：游客真的占一个交互位做动作（排队等柜台、泡在浴桶里、坐在餐桌边），多建同类型建筑=多交互位=排队短。玩家能看到「这家店火爆，该多开一家」。
4. **防挂机**：游客最多住 1-3 晚、停留 2-4 天就走；整个停留期一栋建筑只逛一次。静态小镇（没建什么）的游客满不了条 → 不产出经验。玩家不能靠挂机把城镇升满。

## 游客全程体验（一次完整行程）

### 生成（清晨）
- 游客沿路边生成，带**画像**：40% 均衡、20% 舒适偏好、20% 魔法偏好、20% 奇观偏好。
- 需求上限 = 画像权重 × 等级缩放（**等级越高总需求越高**）：`need = (BASE + (level−1)×PER_LEVEL) × 权重占比`。例：等级1 总需求 150（均衡 50/50/50，侧重 80/35/35），等级5 总需求 350 → 高等级游客更难满足，自然形成「殖民地越高级、要建得越好」的曲线。
- 头顶/面板：**三条进度条（Comfort/Magic/Wonder）** + 画像标签（「偏爱魔法」）+ 精力 + 停留天数。

### 白天（逛街）
- **选目标只看视野内**（`TOURIST_VISION_RADIUS`，默认 48 格、且区块已加载）的可交互建筑。视野内没有合适目标 → **闲逛**，直到视野出现合适的。绝不跨全城寻路去远处建筑。
- 目标评分（Find-Best-Action）：
  `Σ(总三值满意度增益 min(该维需求缺口, round(建筑该维值×coeff))) + 精力紧急加分 − 排队惩罚`
  - 满意度偏好 = 这次访问能把总三值满意度提升多少（潜在总三值 − 现在三值）；某条快满 → 该维增益≈0 → 游客自然转向其它维度（多样性自组织）；单维数值夸张的建筑不再过度吸客。
  - 精力低(<25%) → 强烈偏向回精力建筑；精力=0 → **只能**去回精力建筑。
- 走到建筑 → 走到**某个具体交互位（spot）** → 位子空就**占用**、做该 spot 指定的**动作**（浏览/用餐/泡澡/看展/冥想/取现），站 `duration_ticks`（配粒子/姿态），做完释放、按该建筑 category 模式预设结算（填三条 + 精力变化 + 经济/回精力/取钱）。
- **spot 数量 = 同时交互人数上限**：`interact_spots` 有几个，就有几个游客能同时在该建筑交互；位子全满 → **排队**（在建筑旁等），等太久超时 → 放弃去别处。
- **交互时长由建筑决定**：游客在某 spot 站的 `duration_ticks` 来自该建筑模式预设块的 `interaction_duration_ticks`（shop/service/relax/atm 各块同字段），与 spot 无关。
- **同建筑不同 spot 动作可不同**：每个 `interact_spots` 独立设动作类型，如面包店一个 `browse` 一个 `eat`；游客做所在 spot 的那个动作。

### 精力循环
- 逛建筑消耗精力（shop 交互 -20、service.energy_per_use 正数=消耗），恢复建筑（`relax` category）给正 energy 回精力。
- 精力 0 且视野内没有 relax 恢复建筑 → **闲逛**（不离场），等看到 relax 建筑 / 夜晚入旅店 / 到停留上限。
- 旅店（service.max_occupancy>0）不兜底白天的精力，只管夜晚睡觉。

### 夜晚
- **三条没满**的游客 → 去旅店（beds 建筑）睡一晚（`nightsStayed++`），清晨精力回 100、回到入住点继续逛。
- **三条满**的游客 → **等夜晚再离场**（白天满条先开心闲逛，不立刻走），当晚开心回家，给殖民地经验（法师游客留简历可被酒馆招募）。

### 离场（满足任一）
1. **三条全满 且 夜晚** → 开心离场（经验 + 法师简历）
2. **停留 2-4 天到点** → 离场（**只有满条才有经验**）
3. 夜晚且没有旅店/旅店满 → 离场
4. 长时间没事做（idle）→ 离场

## 每个机制背后的「为什么」（改不动它时要先问为什么）

| 机制 | 为什么 |
|---|---|
| 三条需求条，无惩罚 | 消灭「低于阈值扣分」逼玩家堆最强的问题；普通建筑也正向涨 |
| 画像 + 等级缩放 | 让「多样城镇」是游客自己引导的，不是规则逼的；高等级自然更难（难度曲线） |
| 精力循环 + relax 恢复建筑 | 让餐厅/澡堂/歇脚处有存在意义；一天能逛更多点，单点权重下降 |
| ATM 取钱 | 游客花完随身现金还能取现补钱包继续逛，商店持续卖货 → 殖民地持续收元素；上限=总旅费防刷 |
| 视野限制 | 省寻路开销；行为真实（游客不会瞬移式地跨城去找目标） |
| 停留上限 + 不重置 visitedBuildings | 防挂机；静态小镇满不了条 |
| 满条等夜晚离场 | 玩家能看见游客开心地逛完一整天再走，有情绪回报 |
| spots + 动作 + 排队 | 「真占位做动作」让城镇活起来；**spot 数=同时交互人数**，多建同类型=多交互位=排队短（多建收益）；时长由建筑定、同建筑可多动作，创作者粒度自由 |
| 满条才给经验 | 防刷（经验是里程碑不是流水）；开局建筑数量提高来兜底新手 |
| 扫描器 marker 设动作 | 创作者能精细指定「哪里是什么动作」，不用改 JSON |

## 明确不做什么（防止过度设计）

- **不引入单一 satisfaction**：三条 bar 就是满意度。面板/统计/API 都显示三条（或三条的聚合 min-ratio）。
- **不做 typePreferences**：没有按建筑类型的偏好，目标选择只看需求缺口。
- **排队可见性暂不做**：排队只有机制（游客等着、超时放弃），不做可见的队列标记。
- **精力/经济数值不预先平衡**：`service.energy_per_use`/`shop.goods`/`relax.energy_restore`/`atm.withdraw_amount` 都是建筑级模式预设字段，扫描器可编辑，数值平衡后置。本方案只定机制。
- **不做 category 合并（二阶段）**：`shop`/`service` 保持独立 category，新增 `relax`/`atm`；把四类统一成 `interact` 的 `interaction` 块延后，见 phase-2/README.md。
- **TouristState 不做状态机**：它只是移动标签；活动状态走独立的 `Activity` 枚举。
- **不扩展复杂叙事**：沿用现有 Narrative 体系，按 category（shop/service/relax/atm）同步模板键。
- **不重做寻路**：沿用现有道路/导航，只加「视野内选目标」这层过滤。

## 平衡目标与调参杠杆

> 目标是「休闲玩家几栋高级建筑能喂饱游客」与「低级静态小镇产不出经验」同时成立。这些是唯一允许调平衡的地方：

| 杠杆 | 影响 |
|---|---|
| `TOURIST_BAR_GAIN_COEFF`（默认 1.0） | 每条填充速率 → 几个高级建筑能否在停留期内满条 |
| `TOURIST_NEED_BASE / PER_LEVEL`（默认 150 / 50） | 等级难度曲线陡峭度 |
| `TOURIST_VISION_RADIUS`（默认 48） | 行为真实度 vs 寻路开销 |
| 画像分布（40/20/20/20） | 多样性压力强度（均衡占比越高越容易满足） |
| `TOURIST_STAY_MIN/MAX_DAYS`（2/4） | 休闲 vs 防挂机权衡 |
| `TOURIST_ATM_TRAVEL_FUND_MULTIPLIER`（默认 2.0） | ATM 取现池大小 = 随身现金的倍数（游客总购买力上限） |
| 建筑 `shop{}`/`service{}`/`relax{}`/`atm{}` 数值 | 数值平衡（后置，扫描器可编辑） |

## 非协商项（任何 block 不许偏离）

1. 满条（三条全满）才给经验，且满条**夜晚**离场。
2. 画像总值与游客等级**正相关**。
3. 目标选择**只看视野内**建筑；视野内无目标就**闲逛**。
4. 精力 0 且无恢复建筑 → **闲逛**（不离场）。
5. `interact_spots` **每点带动作种类**；**spot 数量 = 同时交互人数上限**（全满排队）；**交互时长由建筑模式预设块的 `interaction_duration_ticks` 决定**（与 spot 无关）；**同建筑不同 spot 动作可不同**。动作只决定游客活动状态/粒子，**精力/经济效果由建筑 category 模式预设块（shop/service/relax/atm）决定**。
6. **不合并 category**：`shop`/`service` 保持独立 category（模式预设：卖物品/产元素）；新增 `relax`（回精力）、`atm`（取钱）。`interact_spots` 取代 `tourist_interact_aabb`，**不保留**旧 `tourist_interact_aabb` 顶层字段的 JSON 兼容解析；`shop`/`service` 块解析保留。把四类整合成 `interact` 的 `interaction` 块属**二阶段**（短期不做）。
7. **删除** `satisfaction`、`typePreferences`（字段/NBT/接口/调用/配置全清）。
8. `visitedBuildings` 停留期**不重置**。
9. `Activity` 枚举放 `shared/data`（`building/data` 要引用，避免跨模块直接引用）。
10. 核心体验红线：**玩家能看到游客真的在排队/泡澡/睡觉/逛累去歇脚，且多建同类型有实际收益**。
